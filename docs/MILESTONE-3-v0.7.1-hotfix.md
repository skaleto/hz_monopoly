# M3：v0.7.1 热修

- 日期：2026-10-11
- 触发：用户在生产 v0.7.0 报"很多文字被覆盖、很多图片错位"
- 回滚点：生产 v0.7.0（`/opt/hangzhou-partners/releases/v0.7.0-20261010T100114Z`）

## 根因（两项）

1. 棋盘坐标系按 364×508 设计，但 CSS 按机型把棋盘拉成任意比例（375×667 上变 349×327），
   格子固定像素不随缩放 → y 轴压缩 36%，31–57 对节点互相压字（最高 48% 遮挡）；
   320×568 上棋盘高度塌到 228px。
2. 移动端 tile-layer 内边距 6px 与 route-guide 内边距 18px 不一致 → 路线图与格子画在
   两个不同盒子上，错位 12px（用户看到的"图片错位"）。

## 修复

- 棋盘固定 364×508 规范坐标系，shell 内整体等比缩放（--board-scale，ResizeObserver）；
  任何机型几何一致
- 三个图层统一 inset:0；规范块置于样式表末尾压过历史覆盖
- e2e 几何断言按缩放归一；重叠门禁校准 ≤8% AABB（45° 角邻对圆角本体分离，放大截图验证）

## 验证

- npm run verify 全绿（42/42 单元/集成、390×844 双人+Bot 完整 E2E、双模拟门禁）
- 七机型视口扫描（390×844/393×852/375×667/360×740/412×915/414×896/320×568）：
  几何完全一致（缩放不变），无显著重叠对；修复前 SE 32 对/25%、Tiny 57 对/48%

## 已知边界

- 375×667 及更矮的机型上棋盘整体缩小到 ~0.63 倍（格子 ~26px），可读但偏小；
  彻底解决需要重新设计更矮的规范棋盘或引入拖动查看，属后续产品决策
