## 方向

- 目标用户: 在 390×844 左右手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 一屏同时展示顶部 5 个文字按钮、玩家栏 14 个数据项、回合栏 5 个信息/操作项、49 个节点名称与约 25 个项目价格；主视图常驻信息接近 100 个文本单元。棋盘名称/价格约 7px，玩家状态约 8px，顶部/工具按钮约 9px
- 期望结果: 默认态只保留“轮到谁、我的金币、其他玩家金币、当前位置、可用操作、棋盘位置”六类高频信息；价格、城市分、影响力、道具详情、记录和结束本局改为按需展示；默认一屏看完整盘且无需拖动；普通节点名称 canonical 字号 ≥10px，关键图标 canonical 尺寸 ≥24px
- 非目标: 不删除 49 个节点、不改玩法/价格/计分、不减少可用功能、不取消 BGM/音效独立开关；不把所有信息永久隐藏
- 准确对象锚点: GitHub main/生产 v0.8.5；390×844 对局主界面
- 第一个验收样例: 玩家进入对局 1 秒内能回答“轮到谁、我有多少钱、我在哪、能做什么”；屏幕默认看不到项目价格、影响力、道具数、对手城市分和结束本局文字，但均可在一次点击内找到

## 推荐路径

- 推荐方案: “整盘全览 + 关键图标”——默认使用完整棋盘，不发生横向或纵向滚动；49 个节点全部保留，但只在补给、公投、验收、起点、公园 6 个关键动作节点显示 25px 大图标和短标签，其余 43 个节点改为 10.5px 大文字牌；右上“放大”仍可按需进入 1.2×聚焦。继续隐藏项目价格，并保留顶部/玩家栏/回合栏的渐进披露
- 推荐理由: 用户明确把“一屏看全”放在默认聚焦之上；减少重复建筑/卡牌/交通图标比压缩字号更有效，既保留 49 节点与玩法，也把主要节点文字从 7.5px 提高到 10.5px，并把剩余关键图标提高到 25px
- 什么证据会证明推荐错误: 文本牌过多显得单调；关键节点 6 个图标仍不足以帮助扫视；某些全称在小屏中难以快速辨认
- 备选方案: 默认 1.2×聚焦并保留 49 个图标；图标更丰富，但不能一屏看全，已被本轮用户反馈否定
- 当前成熟度允许的动作: D2，推荐路径已由用户授权制作隔离原型；禁止合入主干和发布

## 验收计划

- 环境和数据: 390×844 主门禁，375×667 次门禁；双真人+双 Bot
- 正例: 默认常驻文本单元 ≤62；默认整盘无滚动；普通节点名称 canonical 10.5px、关键节点短标签 9.4px、关键图标 25px；玩家/工具 ≥10px；主要点击区 ≥32px
- 反例: 项目价格仍全量常驻、顶部音乐/音效/记录/结束均为独立文字按钮、对手城市分和我的影响力常驻、全览/聚焦切换后丢失当前节点
- 比较字段/行为: visible text count、computed font-size、tile/target boxes、board scale、scroll range、三问一动作识别
- 容差/性能目标: 不增加网络请求或 DOM 总量；默认横向/纵向均不可滚动；49 个节点无显著重叠，完整文字字形位于节点边界内
- 验收证据工件: 375×667 与 390×844 的默认全览截图、E2E 密度报告

## 原型验证结果

- 390×844: E2E PASS；默认全览 scale=`0.9945`；横向/纵向均不可滚动
- 375×667: E2E PASS；默认全览 scale=`0.9533`；横向/纵向均不可滚动
- 双尺寸共同结果: 49 个棋盘节点保持；可见节点图标从 49 减至 6；普通节点名 canonical=`10.5px`，关键图标=`25px`、短标签=`9.4px`；常驻价格节点=`0`；所有文字字形位于节点边界内；图标与名称重叠=`0`；显著节点重叠=`0`；console errors=`0`
- 信息层级: 顶部仅常驻返回/声音/更多；玩家栏仅常驻头像/名字/金币/回合高亮；道具为 0 时隐藏，建设仅在本人回合且存在候选时显示
- 可逆性: 所有变更仅在 `discovery/ui-density-audit` 隔离分支；未合入 main、未发布，丢弃分支即可完整回退
