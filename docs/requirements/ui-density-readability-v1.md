## 方向

- 目标用户: 在 390×844 左右手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 一屏同时展示顶部 5 个文字按钮、玩家栏 14 个数据项、回合栏 5 个信息/操作项、49 个节点名称与约 25 个项目价格；主视图常驻信息接近 100 个文本单元。棋盘名称/价格约 7px，玩家状态约 8px，顶部/工具按钮约 9px
- 期望结果: 默认态只保留“轮到谁、我的金币、其他玩家金币、当前位置、可用操作、棋盘位置”六类高频信息；价格、城市分、影响力、道具详情、记录和结束本局改为按需展示；默认一屏看完整盘且无需拖动；棋盘节点约减少 1/4，剩余每个节点都保留图案，节点卡、图案和文字整体放大
- 非目标: 不删除投资、事件、地标、公投、验收、公园、补给和双支线等核心玩法；不改项目价格/分红/计分和音频功能；不把详细信息永久隐藏
- 准确对象锚点: GitHub main/生产 v0.8.5；390×844 对局主界面
- 第一个验收样例: 玩家进入对局 1 秒内能回答“轮到谁、我有多少钱、我在哪、能做什么”；屏幕默认看不到项目价格、影响力、道具数、对手城市分和结束本局文字，但均可在一次点击内找到

## 推荐路径

- 推荐方案: “36 节点全图案棋盘”——主环从 34 减至 26，水线/地铁各从 8/7 减至 5，总节点从 49 减至 36（-26.5%）；保留 20 个投资项目、3 个事件、2 个补给、双支线与全部核心特殊节点。剩余每个节点都显示图案和名称，卡片从 42px 放大到 50px、图案 27px、文字 9.5px；默认全览无滚动，仍可按需放大
- 推荐理由: 直接回应用户的澄清；不是把图案删掉，而是通过减少 13 个重复/低频节点，把每个剩余节点的视觉面积提高约 42%，同时保持完整玩法类型和双路线
- 什么证据会证明推荐错误: 36 节点让每圈时长过短、事件频率或现金张力明显失衡；删除的 5 个项目/6 个事件/2 个交通节点让地图风味不足；图审仍认为 50px 卡片不够大
- 备选方案: 32 节点、更大卡片；可读性更强，但规则和节奏变化更大，不作为第一版
- 当前成熟度允许的动作: D2，推荐路径已由用户授权制作隔离原型；禁止合入主干和发布

## 验收计划

- 环境和数据: 390×844 主门禁，375×667 次门禁；双真人+双 Bot
- 正例: 默认常驻文本单元 ≤62；默认整盘无滚动；36 个节点全部同时有图案和名称；节点卡 canonical 50px、图案 27px、名称 9.5px；玩家/工具 ≥10px
- 反例: 项目价格仍全量常驻、顶部音乐/音效/记录/结束均为独立文字按钮、对手城市分和我的影响力常驻、全览/聚焦切换后丢失当前节点

- 容差/性能目标: 不增加网络请求；默认横向/纵向均不可滚动；36 个节点无显著重叠，图案与文字不重叠，完整文字字形位于节点边界内；200 局模拟继续通过现金张力和节奏门禁
