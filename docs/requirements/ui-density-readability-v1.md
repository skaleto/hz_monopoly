## 方向

- 目标用户: 在 390×844 左右手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 一屏同时展示顶部 5 个文字按钮、玩家栏 14 个数据项、回合栏 5 个信息/操作项、49 个节点名称与约 25 个项目价格；主视图常驻信息接近 100 个文本单元。棋盘名称/价格约 7px，玩家状态约 8px，顶部/工具按钮约 9px
- 期望结果: 默认态只保留“轮到谁、我的金币、其他玩家金币、当前位置、可用操作、棋盘位置”六类高频信息；价格、城市分、影响力、道具详情、记录和结束本局改为按需展示；默认棋盘字号 ≥8.5px，玩家/工具文字 ≥10px

- 准确对象锚点: GitHub main/生产 v0.8.5；390×844 对局主界面
- 第一个验收样例: 玩家进入对局 1 秒内能回答“轮到谁、我有多少钱、我在哪、能做什么”；屏幕默认看不到项目价格、影响力、道具数、对手城市分和结束本局文字，但均可在一次点击内找到

## 推荐路径

- 推荐方案: “聚焦棋盘 + 渐进披露”——默认棋盘放大约 1.2 倍并可轻微横向拖动；全览按钮随时恢复整盘。棋盘常驻只显示图标+名称，隐藏约25个价格；顶部合并为首页/声音/更多三个入口；玩家栏只留头像、名字、金币和回合高亮；回合栏合并成一行，道具/建设变成仅在可用时出现的 32px 图标
- 推荐理由: 可把默认常驻文本单元从约98降到约60（约 -39%），同时把棋盘瓦片从约41px放到约49px、7px名称提高到约8.5–9px；利用现有底部空白换取可读性，而不是继续压缩 chrome
- 什么证据会证明推荐错误: 用户无法接受默认看不全整张棋盘；频繁拖动比小字更影响游戏；隐藏对手城市分/项目价格导致决策效率明显下降
- 备选方案: 保持整盘全览，只隐藏价格并合并顶部控件；改动小，但棋盘字号最多提升约10%，不能根治可读性
- 当前成熟度允许的动作: D2，推荐路径已由用户授权制作隔离原型；禁止合入主干和发布

## 原型验证结果

- 390×844: E2E PASS；默认聚焦 scale=`1.2`，全览 scale=`0.9945`；横向可拖动、纵向无需拖动
- 375×667: E2E PASS；默认聚焦 scale=`1.2`，全览 scale=`0.9533`；横向和纵向均可拖动
- 双尺寸共同结果: 49 个棋盘节点保持；常驻价格节点=`0`；玩家栏 DOM=`22`（门禁 `≤22`）；图标与名称重叠=`0`；console errors=`0`
- 信息层级: 顶部仅常驻返回/声音/更多；玩家栏仅常驻头像/名字/金币/回合高亮；道具为 0 时隐藏，建设仅在本人回合且存在候选时显示
- 可逆性: 所有变更仅在 `discovery/ui-density-audit` 隔离分支；未合入 main、未发布，丢弃分支即可完整回退
