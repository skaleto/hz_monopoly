## 推荐路径

- 推荐方案: 以 HARNESS 为唯一规则，把发布压缩为一次性交接、一次只读预检、一次原子切换、一次核心烟测；D4 是授权状态而非额外 commit/阶段
- 推荐理由: 保留 Demo 最有价值的可玩性、数据完整性和回滚能力，同时删除已反复产生噪音与假阴性的重复证据
- 什么证据会证明推荐错误: 新流程导致真实 health/核心玩法/DB 故障未被发现，或无法回滚上一 release
- 备选方案: 维持重流程但减少群消息；仍会保留重复门禁和探针假阴性，不采用
- 当前成熟度允许的动作: 更新并合入流程文档，广播 My Mac；不涉及生产写入
