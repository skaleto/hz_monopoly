## 方向

- 目标用户: 2–4 席熟人私密房玩家，允许 Bot 补位
- 问题/当前行为: M1 可靠且有质感，但隐藏分组几乎不可达、分红冲击弱、Bot 不合伙/建设、事件只靠 Toast、影响力缺少明确用途、终局没有冲刺感
- 期望结果: 约 15 分钟内形成“投资产业板块 → 按参与项目数解锁增益 → 独资或合伙建设 → 明显分红 → 最后三轮冲刺”的可读戏剧弧线
- 非目标: 不做淘汰、抵押、自由交易、复杂股比、重画地图、扩充大卡池、直接发布生产
- 准确对象锚点: `game-core/` 权威规则、`public/` 对局反馈、固定种子模拟与移动端 E2E
- 第一个验收样例: 玩家投资组合中的第2个项目后，能看到 2/3 进度和“还差1项解锁旗舰建设”，而不是依赖隐藏倍率

## 推荐路径

- 推荐方案: 先落地 HARNESS、统一验证和模拟；M2 原型使用5个板块×5个项目，玩家按参与1/2/3/4个项目逐档解锁板块内增益，再叠加五五合伙、最后三轮验收季、三级反馈与“实时得分+公投消耗”的影响力
- 推荐理由: 先让规则可测、可比较，再投入 UI 演出；避免凭感觉反复改数字
- 什么证据会证明推荐错误: 二档/三档几乎不触发或人人同时触发；合伙使等待明显增长；板块增益导致早期锁定胜负；影响力公投无人愿意使用；真人不理解板块进度
- 备选方案: 不做板块增益，仅按项目等级竞争；实现更简单但缺少跨项目成长目标
- 当前成熟度允许的动作: 独立分支实现 harness、模拟器和可丢弃规则原型；禁止发布

## 拍板与已确认决定

- GitHub 仓库与 M1 标签已建立；
- `HARNESS.md` 为唯一规约入口，`npm run verify` 为唯一验证入口；
- 不维护复杂的旧规则兼容：旧规则进行中房间过期，新规则用于新房间；
- M1 初始金币保留按行动顺序 +0/+100/+200/+300；M2 随机先手并依据新经济重新标定，第二轮模拟同时测试等额金币；
- A/B/C 主路径已认可：产业板块分档增益、合伙策略、最后三轮验收季；
- 现有隐藏“成套”实现不视为已完成产品；M2 使用5个板块×5个项目；
- 独资和五五合伙项目对参与者都计1个；增益只作用于该板块自己的项目；
- 1个显示入局进度、2个解锁板块分红增益、3个解锁旗舰建设与城市分、4个解锁板块主导高光但不继续堆租金。

## 验收计划

- 环境和数据: 固定种子模拟；本地 390×844；2/3/4 真人与补 Bot 试玩
- 正例: 板块1/2/3/4档进度可见、三级建设只在参与3个项目后解锁、Bot会合伙/建设、影响力可见且可用于公投、旧规则房间明确过期
- 反例: 半局混用规则、全收集才生效、隐藏倍率、Toast 是唯一反馈、Bot 永远不触发合伙、行动位胜率失控
- 比较字段/行为: 完成率、胜率、投资/合伙/建设、分红分布、重组、领先变化、对局时长、真人理解与再玩意愿
- 容差/性能目标: 模拟100%结束；四行动位约22%–28%；每局产生4–7个二档、约1个三档、四档真实可达但稀有；重大分红P90为付款者现金15%–25%；大多数真人局12–16分钟
- 验收证据工件: `artifacts/balance/`、`artifacts/verify/report.json`、真人试玩记录
