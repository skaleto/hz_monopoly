## 方向

- 目标用户: 2–4 席熟人私密房玩家，允许 Bot 补位
- 问题/当前行为: M1 可靠且有质感，但隐藏分组几乎不可达、分红冲击弱、Bot 不合伙/建设、事件只靠 Toast、影响力缺少明确用途、终局没有冲刺感
- 期望结果: 约 15 分钟内形成“追产业组合 → 独资或合伙 → 建设增值 → 明显分红 → 最后三轮冲刺”的可读戏剧弧线
- 非目标: 不做淘汰、抵押、自由交易、复杂股比、重画地图、扩充大卡池、直接发布生产
- 准确对象锚点: `game-core/` 权威规则、`public/` 对局反馈、固定种子模拟与移动端 E2E
- 第一个验收样例: 玩家投资组合中的第2个项目后，能看到 2/3 进度和“还差1项解锁旗舰建设”，而不是依赖隐藏倍率

## 推荐路径

- 推荐方案: 先落地 HARNESS、统一验证和模拟；M2 原型再实现7×3产业组合、五五合伙策略、最后三轮验收季、三级反馈与“实时得分+公投消耗”的影响力
- 推荐理由: 先让规则可测、可比较，再投入 UI 演出；避免凭感觉反复改数字
- 什么证据会证明推荐错误: 7×3仍难达成；合伙使等待明显增长；租金压力导致早期锁定胜负；影响力公投无人愿意使用；真人不理解组合进度
- 备选方案: 删除产业组合，仅按项目等级竞争；实现更简单但失去传统大富翁最核心的收集目标
- 当前成熟度允许的动作: 独立分支实现 harness、模拟器和可丢弃规则原型；禁止发布

## 验收计划

- 环境和数据: 固定种子模拟；本地 390×844；2/3/4 真人与补 Bot 试玩
- 正例: 组合进度可见、三级建设只在3/3后解锁、Bot会合伙/建设、影响力可见且可用于公投、旧规则房间明确过期
- 反例: 半局混用规则、隐藏倍率、Toast 是唯一反馈、Bot 永远不触发合伙、先手胜率失控
- 比较字段/行为: 完成率、胜率、投资/合伙/建设、分红分布、重组、领先变化、对局时长、真人理解与再玩意愿
- 容差/性能目标: 模拟100%结束；四行动位约22%–28%；至少一组合完成50%–70%；重大分红P90为付款者现金15%–25%；大多数真人局12–16分钟
- 验收证据工件: `artifacts/balance/`、`artifacts/verify/report.json`、真人试玩记录

## 质疑复核

- 是否需要: yes
- 触发原因: 玩法经济与 Bot 策略同时变化，并涉及线上旧房间行为
- 已发现反例: 首轮模拟从截断的 state.log 计数导致错误结论，已改为完整 events 口径；等额初始现金显著扩大先手优势
- 缺失证据: 三个候选的稳定模拟报告、真人试玩与最终事件/影响力交互

- 评审结论: 先完成 harness 和模拟，再决定正式规则数值
