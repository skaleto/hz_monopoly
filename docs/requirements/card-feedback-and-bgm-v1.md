## 方向

- 目标用户: 在手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 卡片用 `rotateY(1080deg→180deg→360deg)` 旋转整个含文字正面，导致镜像字；总显示约 1.5 秒且几乎没有稳定阅读时间；城市事件金币变化只展示文字；游戏没有持续音乐氛围
- 期望结果: 卡片正面永不镜像，入场后至少稳定可读 2 秒；城市事件的金币增减有结构化金额、金币音效和方向一致的动效；对局中有默认开启、可独立关闭的背景音乐
- 非目标: 不改事件概率、金额、规则结算、骰子/移动逻辑，不引入第三方受版权限制音乐，不直接修改生产环境
- 准确对象锚点: `main@16901b9` / 生产 v0.8.0；移动端对局页的城市事件卡、金币反馈与音频控制器
- 第一个验收样例: 触发“梅雨抢修 -180”时，卡片无镜像字、稳定显示 ≥2 秒，出现 `金币 -180` 与损失音效/散落动效；音乐按钮可独立关闭并持久化

## 推荐路径

- 推荐方案: 将卡片翻转改为始终小于 90 度的正面 3D 倾斜入场并设置 `backface-visibility:hidden`；动画约 0.8 秒、稳定阅读约 2.4 秒；服务端为 `CITY_EVENT_RESOLVED` 输出 `cashChanges`；客户端在卡片上显示结构化金额并播放增/减金币音效和粒子；在现有 AudioContext 内增加原创程序化循环 BGM 与独立 `音乐开/关` 开关
- 推荐理由: 直接消除镜像根因；金额真值仍由服务端权威；复用单一 AudioContext 与生命周期，避免额外音频资产、版权和并发播放问题
- 什么证据会证明推荐错误: 任一关键帧旋转跨过 ±90 度、稳定阅读 <2 秒、金额与 state diff 不一致、音乐关闭/离页后仍有调度或声音、音效关闭连带关闭音乐
- 备选方案: 引入外部 BGM 文件；音色可能更丰富，但增加版权、体积和首屏加载风险，本轮不采用
- 当前成熟度允许的动作: 独立 worktree 实施、测试和评审；不得合入 main 或发布

## 质疑复核

- 是否需要: no
- 触发原因: 单仓库、可逆 C1 反馈改造；不涉及生产写入、权限、安全或 DB 迁移
- 已发现反例: 只加 `backface-visibility` 会让 180 度阶段整卡消失；只延长 1500ms 定时器仍没有足够稳定阅读时间；把音乐绑在音效开关上不满足独立控制
- 缺失证据: 用户对候选 BGM 音色和卡片节奏的真人试听验收
- 已删除的不必要设计: 不增加第二个 AudioContext，不下载第三方音乐，不从事件文案解析金额
- 评审结论: 可进入 D3 实施，完成自动门禁后交付试听候选
