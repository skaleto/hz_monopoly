## 方向

- 目标用户: 在手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 投掷入口只按最终快照的 current player 判断，缺少“命令已提交/事件仍在播放”的本地锁，可能在别人或 Bot 的动画尚未播完时重新出现；普通节点图标为 22px、项目节点为 17px；背景高饱和且细节密集；BGM master gain=.22、步长 300ms、声部与重拍较弱
- 期望结果: 投掷入口只在“当前本人可投掷且没有命令在途、没有事件回放”时可见；不扩大图标布局框，通过裁减素材内边距让普通/项目图标主体分别放大约 16%/12% 且零文字/价格碰撞；棋盘容器按 364:508 实际内容收紧，上下蓝色空带各不超过 5px；正式采用方案 A“西湖水园”作为可复现竖屏棋盘源与 v4 运行资源
- 非目标: 不改骰子权威随机、移动/投资/事件数值、49 节点坐标和路线拓扑；本次不改 BGM，线上程序化音乐保持 v0.8.1，AI 编曲音轨及其许可证据另行验收；不直接覆盖生产 v0.8.1
- 准确对象锚点: origin/main@`ab22c0b14a774428d7860e182e3ab8d10328d35c` / 生产 v0.8.1；隔离分支 `feat/v082-clarity-bgm`
- 第一个验收样例: A 玩家点击投掷后，从 `DICE_ROLLED` 到 Bot/其他玩家移动与回合事件播完之前，A/B 两端都不显示 A 的投掷入口；只有服务端最终状态确认为当前本人且事件队列空闲时才重新显示

## 推荐路径

- 投掷入口: 新增本地 roll command-in-flight 与 event playback 锁；发送 ROLL_DICE 或收到 game.events 时立即统一隐藏骰子命中层和文案，只有权威快照已应用且事件队列空闲时重新调度
- 图标: 保持 41px 格子与 22/17px CSS 布局框不变；普通节点源图中心裁切 440/512、项目图裁切 456/512 后生成 v2 WebP，让主体约放大 16%/12%，不挤占名称/价格空间
- 棋盘空间: 小屏 `.board-shell` 按可用宽度与 364:508 比例计算，第三行不再拉满；上下蓝色空带各 `<=5px`
- 背景: 方案 A 西湖水园定稿；以 `board_water_garden.png` 作为 728×1016 构建源，由 `build:assets` 生成 `board.v4.webp`，页面不再引用横版 `board.v3.webp`
- BGM: 放弃本轮程序化加强版并回退线上逻辑；正式方案等待 Adobe Firefly / SOUNDRAW / Beatoven 等生成的商用许可纯音乐，再做无缝循环、响度、音效避让与 H5 压缩
- 什么证据会证明推荐错误: 任一非当前玩家/事件回放窗口仍可见投掷入口；图标压住名称或价格；背景让路线/节点对比更差；BGM 失真、刺耳、压过关键音效或关闭后仍调度
- 备选方案: 只提高 CSS 音量或全图统一放大；不能解决节奏推进感和项目节点空间差异，不采用
- 当前成熟度允许的动作: D4 已通过；允许 My Mac 仅从最终 D4 唯一完整 SHA fresh 构建全新 v0.8.2 release，并按原子切换与失败精确回滚 v0.8.1 的契约执行
