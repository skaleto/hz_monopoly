## 方向

- 目标用户: 在手机上进行 2–4 人熟人对局的玩家
- 问题/当前行为: 投掷入口只按最终快照的 current player 判断，缺少“命令已提交/事件仍在播放”的本地锁，可能在别人或 Bot 的动画尚未播完时重新出现；普通节点图标为 22px、项目节点为 17px；背景高饱和且细节密集；BGM master gain=.22、步长 300ms、声部与重拍较弱
- 期望结果: 投掷入口只在“当前本人可投掷且没有命令在途、没有事件回放”时可见；不扩大图标布局框，通过裁减素材内边距让普通/项目图标主体分别放大约 16%/12% 且零文字/价格碰撞；提供三套同风格低噪声背景实机候选；BGM 提升可听响度、低频和节奏推进感，仍可独立开关并遵守生命周期
- 非目标: 不改骰子权威随机、移动/投资/事件数值、49 节点坐标和路线拓扑；背景未选定前不替换生产素材；不直接修改生产 v0.8.1
- 准确对象锚点: origin/main@`ab22c0b14a774428d7860e182e3ab8d10328d35c` / 生产 v0.8.1；隔离分支 `feat/v082-clarity-bgm`
- 第一个验收样例: A 玩家点击投掷后，从 `DICE_ROLLED` 到 Bot/其他玩家移动与回合事件播完之前，A/B 两端都不显示 A 的投掷入口；只有服务端最终状态确认为当前本人且事件队列空闲时才重新显示

## 推荐路径

- 投掷入口: 新增本地 roll command-in-flight 与 event playback 锁；发送 ROLL_DICE 或收到 game.events 时立即统一隐藏骰子命中层和文案，只有权威快照已应用且事件队列空闲时重新调度
- 图标: 保持 41px 格子与 22/17px CSS 布局框不变；普通节点源图中心裁切 440/512、项目图裁切 456/512 后生成 v2 WebP，让主体约放大 16%/12%，不挤占名称/价格空间
- 背景候选: 从同一 Q 版西湖源图生成三版可复现低噪声方向——A 清爽湖蓝（轻减饱和/轻柔化）、B 晨雾青绿（中度减饱和/雾感）、C 淡彩宣纸（低饱和/暖色纸感）；先截图选型，不接入生产
- BGM: master gain 约 .22→.42，步长 300→260ms；增加偶数拍低音、每两拍 kick 与高音点缀，保留单 AudioContext、独立开关和离页停止
- 什么证据会证明推荐错误: 任一非当前玩家/事件回放窗口仍可见投掷入口；图标压住名称或价格；背景让路线/节点对比更差；BGM 失真、刺耳、压过关键音效或关闭后仍调度
- 备选方案: 只提高 CSS 音量或全图统一放大；不能解决节奏推进感和项目节点空间差异，不采用
- 当前成熟度允许的动作: 在隔离 worktree 实施、生成预览、运行测试和交用户选型；禁止合入或发布

## 验收计划

- 375×667、390×844；双真人+双 Bot；本人/他人/命令在途/骰子动画/移动动画/最终轮转五个时点
- 投掷入口: `#rollButton`、`#rollPromptButton` 与 ready stage 在非本人或事件播放中全部隐藏；服务端最终确认本人回合后才同时恢复
- 图标: CSS 布局框普通=22px、项目=17px；运行时全部引用 v2 裁切素材；49 节点图标均位于格内，名称/价格零重叠、零截断、AABB >8%=0
- BGM: profile、master gain、stepMs、声部数进入 trace；音乐/音效四种开关组合与 hidden/home/finished 生命周期保持全绿
- 背景: 三版保持相同尺寸、路线识别度和节点对比；由用户主观选择，不用自动指标替代
- 停止条件: 任一跨玩家投掷入口回归、布局碰撞、音频生命周期泄漏、完整 verify 失败或用户不接受背景/BGM

## 质疑复核

- 是否需要: no
- 触发原因: 单仓库、可逆 C1 客户端与预览素材改动，不涉及规则、DB、权限或生产写入；由同一 Agent 按七维清单自检

- 已删除的不必要设计: 不新增服务端字段，不替换骰子状态机，不引入第二个 AudioContext，不在用户选型前提交任一背景为正式资产
