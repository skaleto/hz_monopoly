# 房间 941415：旧快照导致事件与房间状态分叉

- 日期：2026-10-09
- 影响版本：v0.4.5；v0.5.0 仍可复现旧快照问题
- 发现方式：用户报告岔路卡住、结束本局显示 undefined
- 生产处理：全程只读取证；未直接修改房间或数据库
- 修复版本：v0.5.1（持久化与旧快照），v0.5.2（生命周期与终局）

## 用户影响

房间 941415 在岔路选择后表面卡在 `decision`。用户随后看到服务端 TypeError 原文，结束本局也难以生效；重新进入旧房时还会播放积压的 Bot 事件、Toast 和音效。

## 根因

旧 `hangzhou-v1.2` 快照里的玩家对象缺少 `items` 等后来新增字段。P1 选择岔路后：

1. 服务端先将 seq248–252 写入 `game_events`；
2. 随后的 P2 Bot 接管读取 `player.items.length`，因 `items` 为 `undefined` 抛出 TypeError；
3. 异常发生在房间快照保存前，`rooms.state_json` 因此停在 seq247；
4. 后续连接和断开只从数据库重新读取并写回 seq247，没有发生“已保存252后再回退”。

客户端又将权威状态同步与视觉动画放在同一串行队列中，导致：

- 23 条同批历史事件逐条播放时，房间 `version` 不能及时推进；
- END_GAME 容易携带旧版本被拒绝；
- 返回首页后旧队列、骰子、Toast、金币和音频仍继续播放。

## 修复

- 旧快照进入规则核前统一补齐 `items=[]`、`diceBonus=0`、`rentShield=false`、`reviewTurns=0` 等字段；
- 玩家命令与全部 Bot 连锁先在内存完成，再在同一 SQLite transaction 中提交 events + snapshot；
- `saveRoom` 拒绝 seq/version 回退，membership 写入进入同一 room queue；
- 同 user/room 维护活跃 socket 计数，旧 socket 关闭不会误启动托管；
- END_GAME 对房主 stale-safe，重复提交返回幂等 ack；
- 客户端先同步权威 snapshot/version，再播放可取消的视觉队列；
- 离页、切房和终局取消 socket、事件队列、骰子、Toast、金币、庆祝与音频；
- 增加 ws open/close、activeSockets、托管 timer 和命令拒绝的脱敏日志。

## 永久回归

- `tests/game-core.test.js`：v1.2 缺字段迁移、岔路恢复、房主终局；
- `tests/integration.test.js`：原子回滚、stale room write、多 socket 防误托管、stale/repeated END_GAME、单真人离页不托管；
- `tests/e2e.js`：长动画中 goHome 后声音、金币、Toast、骰子和庆祝全部停止。

## 防复发规则

- 新字段必须进入快照归一化与旧版本测试；
- 事件和房间快照不得分两次提交；
- 权威状态同步不得等待视觉动画；
- 生命周期资源必须绑定房间代际并可取消；
- 生产错误不得把原始 TypeError 直接展示给用户。
